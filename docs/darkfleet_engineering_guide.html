Module 1: Maritime Telemetry & Data Acquisition Architecture

1.1 Understanding AIS (Automatic Identification System) & The NMEA 0183 Protocol

The International Maritime Organization (IMO) under SOLAS Regulation V/19 mandates that all commercial vessels exceeding 300 gross tonnage on international voyages carry Class-A AIS transponders. These transponders broadcast VHF radio signals (161.975 MHz and 162.025 MHz) to terrestrial base stations and Low Earth Orbit (LEO) satellite constellations (such as Spire, exactEarth, and Iridium).

AIS signals are encapsulated in the NMEA 0183 standard using 6-bit ASCII armoring in !AIVDM (received from other vessels) and !AIVDO (own ship broadcast) sentences: 

!AIVDM,1,1,,B,13u?etPv2;0n:dDPHeavy000000,0*52

When decoded according to the ITU-R M.1371 technical specification, this bitstream unpacks into two fundamental message types required for maritime intelligence:

Message ID Classification Broadcast Interval Key Decoded Attributes
Type 1, 2, 3 Dynamic Position Report 2 to 10 seconds (moving)
3 minutes (at anchor)		 MMSI (9-digit identifier), Latitude, Longitude, Speed Over Ground (SOG), Course Over Ground (COG), True Heading, Navigational Status.
Type 5 Static & Voyage Data Every 6 minutes IMO Number, Call Sign, Vessel Name, Ship Type / Dimensions, Destination, ETA, Maximum Present Static Draught (Draft in meters).

Traditional CSV storage is catastrophic for high-frequency telemetry. A raw 112,000-row AIS dataset in uncompressed CSV format consumes ~45 MB of disk space and incurs massive I/O overhead. DarkFleet-IQ serializes all raw ingestion directly into Apache Parquet with Snappy compression.

2.2 Why DuckDB as the Analytical Kernel?

While traditional engineering teams immediately spin up heavyweight PostgreSQL or Snowflake clusters, DarkFleet-IQ utilizes DuckDB. DuckDB is an in-process, columnar OLAP database engine engineered for high-performance vectorized analytics:

  • Vectorized Morsel-Driven Execution: DuckDB processes data in CPU cache-friendly vectors of 2,048 values. Operations like average speed, geospatial bounding, or draft standard deviations leverage CPU SIMD (Single Instruction, Multiple Data) instructions.
  • Zero-Copy Arrow Integration: DuckDB exchanges records directly with Python Polars and Pandas without costly memory serialization or network socket overhead.
  • Embedded Portability: The entire 112,000+ ping lakehouse resides in a single data/darkfleet.duckdb file (12.1 MB), allowing instant deployment to cloud servers with sub-15ms query execution.

Module 4: Advanced SQL Spatial & Windowing Logic

4.1 Detecting Transponder Blackouts via Bidirectional Windowing

When a rogue vessel enters an illicit zone, it turns off its transponder to mask its activities, then reappears hours later miles away. Detecting this requires calculating the elapsed time ($\Delta t$) and distance gap between consecutive pings for each vessel.

A naive self-join costs $O(N^2)$ comparisons. DarkFleet-IQ uses bidirectional SQL window functions to achieve $O(N \log N)$ execution: 

-- Intermediate Model: int_vessel_drift.sql
WITH ordered_telemetry AS (
    SELECT
        ping_id,
        vessel_id,
        timestamp,
        latitude,
        longitude,
        speed_knots,
        draft_m,
        -- Look back to prior ping
        LAG(timestamp, 1) OVER (
            PARTITION BY vessel_id ORDER BY timestamp ASC
        ) AS prev_timestamp,
        LAG(latitude, 1) OVER (
            PARTITION BY vessel_id ORDER BY timestamp ASC
        ) AS prev_lat,
        LAG(longitude, 1) OVER (
            PARTITION BY vessel_id ORDER BY timestamp ASC
        ) AS prev_lon,
        -- Look forward to next ping
        LEAD(timestamp, 1) OVER (
            PARTITION BY vessel_id ORDER BY timestamp ASC
        ) AS next_timestamp
    FROM {{ ref('stg_ais_pings') }}
)
SELECT
    *,
    DATE_DIFF('minute', prev_timestamp, timestamp) AS gap_minutes,
    CASE 
        WHEN DATE_DIFF('minute', prev_timestamp, timestamp) > 360 THEN 1 
        ELSE 0 
    END AS is_blackout_event
FROM ordered_telemetry;

4.2 Great-Circle Haversine Distance in Pure ANSI SQL

To prove that a vessel traveled impossibly far while "dark" (indicating transponder spoofing or high-speed evasion), DarkFleet-IQ computes the spherical Haversine distance directly within DuckDB SQL:

\( d = 2R \cdot \arcsin\left( \sqrt{\sin^2\left(\frac{\Delta \phi}{2}\right) + \cos(\phi_1)\cos(\phi_2)\sin^2\left(\frac{\Delta \lambda}{2}\right)} \right) \) 
-- Haversine Great-Circle Calculation in DuckDB SQL (Earth Radius R = 6371 km)
SELECT
    vessel_id,
    prev_timestamp,
    timestamp AS reappearance_timestamp,
    gap_minutes,
    2 * 6371 * ASIN(
        SQRT(
            POWER(SIN(RADIANS(latitude - prev_lat) / 2), 2) +
            COS(RADIANS(prev_lat)) * COS(RADIANS(latitude)) *
            POWER(SIN(RADIANS(longitude - prev_lon) / 2), 2)
        )
    ) AS haversine_distance_km
FROM ordered_telemetry
WHERE gap_minutes > 360;

Module 5: Statistical Forensics & Empirical Rigor (SciPy)

5.1 Why Visual Dashboards Are Not Legal Proof

A compliance officer or intelligence analyst cannot present a visual chart in court and say "it looks like the vessel discharged oil." Visual patterns can be random flukes. Statistical forensics requires formal hypothesis testing to disprove the null hypothesis ($H_0$) with mathematical certainty.

5.2 Hypothesis 1: Physical Cargo Discharge Proved via Welch's Two-Sample t-Test

Physical Law: A loaded Very Large Crude Carrier (VLCC) carrying 2 million barrels of crude oil draws ~21 meters of draft (hull depth submerged in water). If it discharges its oil into another tanker mid-sea, the Archimedes buoyant force pushes the hull upward, decreasing draft to ~9–11 meters (ballast condition).

  • Null Hypothesis (\(H_0\)): Mean draft before the blackout event equals mean draft after reappearance (\(\mu_{\text{pre}} = \mu_{\text{post}}\)).
  • Alternative Hypothesis (\(H_1\)): Mean draft significantly decreases post-reappearance (\(\mu_{\text{post}} < \mu_{\text{pre}}\)).
🔬 Why Welch's Formulation Over Student's t-Test?
Standard Student's t-test assumes homoskedasticity (equal variance \(\sigma_1^2 = \sigma_2^2\)). Legitimate ships maintain tightly controlled drafts (\(s_1^2 \approx 0.12\)), whereas shadow fleet vessels undergoing mid-sea lightering exhibit high variance (\(s_2^2 \approx 14.8\)). Welch's t-test applies Satterthwaite's approximation to degrees of freedom, preventing false positives. 
# Execution in Python (analysis/statistical_forensics.py)
from scipy import stats
import numpy as np

# Ingest empirical draft records from DuckDB
draft_pre = df_shadow.filter(pl.col("event_phase") == "PRE")["draft_m"].to_numpy()

# Compute Cohen's d Effect Size

                     (len(draft_pre) + len(draft_post) - 2))

8.2 Top 5 Hard Technical Questions Interviewers Will Ask & How to Answer

Q1: "Why did you use DuckDB instead of PostgreSQL for this project?"

Answer: "PostgreSQL is an OLTP row-store optimized for transactional concurrency. When scanning 112k+ rows to compute average draft shifts or windowed time deltas, Postgres reads every unused attribute into memory. DuckDB is a columnar OLAP engine that utilizes vectorized morsel-driven execution, running SIMD instructions across 2,048-element vectors. This reduced my analytical query latency from ~400ms in Postgres to under 15ms in DuckDB with zero database server overhead."

Q2: "How did you handle the fact that AIS satellite pings can arrive out of order?"

Answer: "LEO satellites pass over targets at varying orbital angles, causing ping reception timestamps to arrive out of chronological sequence. In my dbt intermediate layer, I partitioned strictly by vessel_id and enforced an explicit ORDER BY timestamp ASC in my window function clauses. Additionally, I implemented a dbt test asserting that computed time deltas between adjacent rows are non-negative."

Q3: "Why choose Welch's t-test over a standard Student's t-test or Mann-Whitney U?"

Answer: "Student's t-test assumes homoskedasticity (equal variance). Normal commercial vessels maintain stable ballast drafts with near-zero variance, while rogue vessels undergoing mid-sea discharge have high variance. Welch's t-test uses the Satterthwaite approximation to adjust degrees of freedom for unequal variances. I chose it over Mann-Whitney U because vessel draft distributions closely follow a normal distribution across operational phases, and Welch's t-test provides higher statistical power for parametric mean shift estimation."

Q4: "How would you scale this pipeline from 112,000 pings to 10 billion pings in production?"

Answer: "I would maintain the columnar Parquet storage but partition the lakehouse using a Hive-style layout by year/month/day/geohash_prefix. Ingestion would stream through Apache Kafka into Apache Iceberg or Delta Lake tables. For querying, DuckDB can query multi-terabyte Parquet files directly from Amazon S3 using HTTP range requests without downloading the full dataset, or the SQL logic can run directly on dbt-Snowflake/Databricks."

Q5: "How did you prevent the GenAI briefing engine from hallucinating numbers?"

Answer: "The LLM is strictly prohibited from doing math or extracting raw metrics on its own. DuckDB and SciPy execute all queries, draft differences, and statistical tests deterministically. The resulting numbers are formatted into a rigid JSON payload. The LLM prompt is constrained via a system prompt that mandates every factual claim and numerical value map directly to a verified field in the input payload, turning the model into a drafting tool rather than an analytical engine."
